## 1. Product in one paragraph

"Notion for maintenance": a documentation, planning and inventory tool for factory maintenance
teams, mobile-first and PWA-capable. It owns work orders, preventive schedules, the history log,
inventory and reporting; it *reads* live machine health/energy/faults from VIDE+Cortex and *is a
client of* the Cogitex Verified Technician marketplace. Core promise: a fault detected by VIDE can
become a confirmed, dispatched repair request in a few taps — with confidence and human-in-the-loop
at every boundary where sensor inference meets real-world action.

## 2. Stack decisions

| Concern | Choice | Rationale / notes |
|---|---|---|
| Framework | **Next.js (App Router) + React, TypeScript `strict`** | Server components for dense lists, route handlers for webhooks/agent/actions, one deployable. |
| UI primitives | **shadcn/ui**, restyled onto VIDE tokens | Copy-in components; we restyle to the extracted design language (§3) instead of inventing style. |
| Styling | **Tailwind CSS** (latest stable) | Token-driven CSS variables in `src/styles/globals.css`, matching VIDE verbatim; `src/styles/tokens.ts` mirrors them for TS use. |
| Data fetching | **TanStack Query v5** (client) + server actions / route handlers | Lists filterable/searchable; mutations funnel through one service layer. |
| Database | **PostgreSQL 16 + Drizzle ORM + drizzle-kit** | Typed SQL, plain migrations, easy tenancy filters. Prisma acceptable too — pending answer on what VIDE main itself runs (see `OPEN_QUESTIONS.md` Q2). Dev/test fallback: in-process **PGlite** (same SQL) when `DATABASE_URL` is unset. |
| Validation | **zod** everywhere (HTTP bodies, webhooks, agent tool args, config) | Shared schemas are reused by contract tests and the mock server. |
| Charts | **Recharts** | Enough for trends; consistent with Next/TS. |
| Reports PDF | **@react-pdf/renderer** rendered server-side in a route handler; CSV generated by a small serializer | Fonts bundled; no headless browser dependency. |
| Auth | **Built-in session auth** — `jose` HS256 session cookie (30d), scrypt password credentials, per-request Ctx reload of org/roles from the DB; exposed through the `IdentityClient` adapter seam | M0 implementation (VIDE ships no SSO today — see `OPEN_QUESTIONS.md` Q3); a shared-SSO adapter can replace it with zero UI change. Auth.js remains possible later. |
| Jobs/scheduler | **DB-backed queue tables** + a worker process (cron via scheduler entrypoint) | No external broker; survives restarts; visible state, retry counts, dead-letter statuses. |
| PWA/offline | Service worker (app-shell caching) + IndexedDB (Dexie) draft queue for technicians | Checklist completions queue offline, sync on reconnect. M1+ seeds this; hardened in M8. |
| LLM (agent) | Provider-agnostic gateway route; adapter per provider (OpenAI-compatible first), key/model/provider in env | Brief 5.8 + 7: swappable by config, never hard-coded. |
| Testing | Vitest (unit), Playwright (e2e), PG test DB via PGlite (in-process Postgres; testcontainers option for parity later) | Tenancy-isolation suite runs in CI per brief §7. |
| Tooling | npm, ESLint + Prettier (lint pass lands with M1), GitHub Actions CI, Node ≥ 20 LTS | |
| Deploy | **Vercel** + managed Postgres (**Neon**) for the shareable demo | `DATABASE_URL` + `AUTH_SECRET` env vars; README carries exact steps (`npm run db:migrate` against the Neon URL once). Resolves `OPEN_QUESTIONS.md` Q12. |

**Money & time conventions (hard rules):**
- Money is stored as **integer kobo** + a `currency` column (default org currency `NGN`). Never floats.
- Timestamps stored **UTC** (`timestamptz`); displayed in **Africa/Lagos** via `src/lib/time.ts` formatting helpers. Timezone is an org setting defaulting to Africa/Lagos (see `OPEN_QUESTIONS.md` Q10).

### 3.2 Type, shape, motion, behavior

- **Typography:** `'JetBrains Mono','Consolas',monospace` for everything. Observed steps:
  eyebrow/label 9px + letterspacing 1.5–2px (uppercase); table/kv 11px; body/lead 12px;
  buttons 11px bold; nav 12px; titles 13–16px bold; tile value 22px bold with 11px unit suffix.
- **Shape:** zero border-radius everywhere; **2px solid borders**; 6px × 6px square "notch" at the
  top-left corner of cards (`card::before`); inset 1px black ring inside status dots.
- **Motion:** `steps(4)` pulse on value change (tiles re-highlight from accent → ink over 0.6s);
  `:active` transform `translate(1px,1px)` on buttons; toast bottom-center, 2.2s dismiss.
- **Structural behaviors replicated:** 230px sidebar (brand block, "WORKSPACE" eyebrow nav with
  3px left accent bar for active item, footer status dot), topbar crumb/title, footerbar,
  kv rows with dashed separators, urgency color classes, `.empty-state` dashed panels, live/err
  badge variants, theme toggle button in topbar persisted to `localStorage`.
- **Component map (VIDE class → our component):**
  .tile → `<Tile>` (dashboard KPI), .card → `<Card>` panel, .eyebrow → `<Eyebrow>`, .kv → `<KVList>`,
  .grid4/.grid2 → responsive `Grid` presets (2-col collapse < 900px), .badge → `<StatusBadge>`,
  .signal → attention-queue row, .empty-state → `<EmptyState>`, toast → `<Toast>`,
  sidebar/topbar/footerbar → `<AppShell>`; nav links become route-based active state.

### 3.3 Adaptations (flagged, not silent)

- Aesthetic floors: body text **≥ 12px** and `--dim` contrast checked to keep WCAG AA (9px
  eyebrows are decorative labels only). Approved adjustment to keep readability on mid-range phones.
- Same class vocabulary reused so VIDE and Planner screenshots remain visually continuous.
- New app adds: date pickers, tables, kanban, chat — all restyled to these tokens (sharp corners,
  2px borders, mono type), no rounded/shadow-heavy third-party look will ship.

## 4. Tenancy, auth, roles

- Every mutation/read path builds a **`Ctx { orgId, userId, roles }`** from the session server-side.
  The org never comes from request payloads or cookies set by clients ("organization and user come
  from the session, never from model output" — enforced literally for the agent too).
- All tenant tables carry `organization_id`; repositories are functions that take `Ctx` and always
  filter by it. There is no code path that queries a tenant table without `Ctx` (CI test + lint grep).
- Role matrix (server-enforced; same matrix also feeds UI affordances):

| Ability | Owner/Admin | Mgmt Manager | Technician | Viewer | External Technician |
|---|---|---|---|---|---|
| View machines/plans/inventory/reports | ✓ | ✓ | ✓ | ✓ | limited: their jobs + machine briefs |
| Create/edit machines, schedules, lifecycle | ✓ | ✓ | — | — | — |
| Work order: draft/plan/assign/verify/close | ✓ | ✓ | — | — | — |
| Work order: start/complete/awaiting-parts | ✓ | ✓ | ✓ | — | ✓ (own) |
| Execute checklist, photos, notes | ✓ | ✓ | ✓ | — | ✓ |
| Inventory edit, ledger ops, suppliers | ✓ | ✓ | issue items on own WO | — | — |
| Repair requests: send/confirm/rate | ✓ | ✓ | — | — | view own + report |
| Decommission/reactivate, hard delete | ✓ | manager proposes, admin executes | — | — | — |
| Settings, users, roles | ✓ | — | — | — | — |

- `external_technician` sessions carry an `actor_bind` (marketplace identity ↔ repair request),
  visually grounded to **only** their assigned WO and its machine brief.
- **Audit log** row written for every create/update/delete/status change (append-only).

## 5. Ownership boundaries (mirrors brief §3, mapped to code)

| Something | Owner | In this app it lives in |
|---|---|---|
| Telemetry, fault detection/prediction (Cortex), health score, alert rules, device pairing, energy metering details, marketplace logic | VIDE family | we consume via `lib/integrations/*` only |
| Work orders, PM schedules, checklists, history, inventory, costs, reports, agent, machine business records | **this app** | `src/server/services/*` + `src/server/db/schema/*` |
| Shared identity & login, shared notification delivery (push/WhatsApp/SMS) | VIDE | `IdentityClient` / `NotificationClient` interfaces, adapter swap later |
We never copy raw telemetry: only bounded snapshots/summaries (fault evidence, hourly health, daily
energy) are persisted, for reports/trends — see Data minimization in §9.

## 7. Data flows (key paths)

**7.1 Request lifecycle (all reads/writes)**

```
Browser (TanStack Query / server actions)
        │  session cookie
        ▼
Next.js route/action  ──►  Ctx built from session (orgId, userId, roles)
        ▼
service layer (business rules, state machines, audit, notifications)
   ├─► repositories (Drizzle, always org-scoped)
   └─► integration adapters (Vide/Cortex/Marketplace/Notification/Identity; mock-first)
```

**7.2 Webhook ingestion (fault.raised, fault.cleared, device.offline/online)**

```
VIDE/Cortex ──HTTPS POST──► api/v1/webhooks/[source]
  verify HMAC signature + timestamp skew (±5 min)
  202 accepted ──► store raw payload in webhook_in_events (headers + body)
  dedupe on (source, event_id)
  enqueue job ──► worker: parse (zod), map machine_ref → machine (tag mapping),
                  write bounded snapshot (fault_events), refresh caches, notify, maybe create fault-linked WO inputs
```

**7.3 PM auto-generation worker (runs on interval)**

```
for each active schedule (calendar | runtime_hours | condition):
  calendar      → crontab/interval days since last run
  runtime_hours → machine.runtime_hours (from VIDE runtime feed) >= next_due_hours
  condition     → VIDE health score < threshold OR open fault ≥ severity (with cooldown)
  → creates work_order (status draft/planned, source=schedule, linked schedule_id)
  → reservation draft for parts shopping list; notify manager (deduped)
```

**7.4 Repair request compile → marketplace**

```
UI "Request technician" (fault | WO | machine) → compile service:
  machine profile snapshot + fault payload + confidence + health trend + suggested
  parts (BOM∩inventory) + tools/skill + urgency (human-checked, editable)
   → Confirmation screen (confidence displayed; fields editable)
   → MarketplaceClient.createRepairRequest (typed) → repair_requests row (sent)
   → status fed back by webhooks (matched/quoted/accepted/en_route/on_site/completed)
   → manager confirms + rates → outcome report attached to the WO
   → confirmed root cause pushed back to VIDE (CortexClient.sendConfirmedRootCause)
```

**7.5 Agent chat**

```
user msg → agent/chat route ─► gateway (provider from env) ─► tool registry
   read tools: org/user scoped from Ctx only; tools never accept org params from the model
   write tools: return "proposed action" objects to the UI → explicit confirm → execute
every tool call logged (agent_tool_logs); every answer carries citations (record ids);
documents/notes are untrusted text — never executed/instruction-bearing
```

**7.6 Offline (technician PWA)**

```
no network → service worker serves shell; checklist drafts + photo intents queue in IndexedDB
reconnect → sync worker replays in order with idempotency keys (WO id + step), conflicts surface
as "resolve" toasts; snapshot caches of machine briefs are pre-cached for assigned WOs.
```

## 8. Integration layer (summary; full detail in `INTEGRATION_CONTRACTS.md`)

- Five typed clients (`VideClient`, `CortexClient`, `MarketplaceClient`,
  `NotificationClient`, `IdentityClient`) defined as TS interfaces; **mock adapters first**;
  real adapters read base URLs/keys from env only. Swapping mock→real requires zero UI change.
- Webhooks in: signature-verified, raw-stored, deduped by event id, processed asynchronously.
- Mock open server (`mocks/server.mts`) + fixtures: a pump with rising vibration trend, a motor
  with voltage-sag pattern, and baseline-healthy machines, so the whole app is demoable before
  any VIDE deployment exists.

## 9. Non-functional plan

- **Data minimization:** no raw telemetry rows. Boundaries: fault evidence snapshots ≤ 32 KB each;
  health samples hourly (90-day retention); energy daily aggregates (400-day retention);
  runtime counters; device status current-state only. Purge job compacts older-than-retention data.
- **Rate limiting:** token bucket middleware per session/IP on API routes (esp. webhooks + agent).
- **Uploads:** storage adapter (local disk/S3 — see Q6), upload scanning hook (pluggable scanner;
  default quarantine-noted no-op until real scanner chosen), mime + size caps, checksums.
- **Secrets:** `.env.example` only names vars (`VIDE_API_BASE_URL`, `VIDE_WEBHOOK_SECRET`,
  `MARKETPLACE_API_BASE_URL`, `MARKETPLACE_API_KEY`, `NOTIFICATION_…`, `IDENTITY_*`, `LLM_PROVIDER`,
  `LLM_API_KEY`, `DATABASE_URL`, …). No hard-coded URLs or keys anywhere (brief §8).
- **Performance budgets:** ≤ 3s time-to-interactive on mid-range phone/3G-first; all lists paginated
  + server-filtered; charts fetch only summaries; first paint via server components.
- **A11y:** keyboard navigable, focus-visible (2px accent outline on dark), labels on all inputs,
  color is never the only signal (icons/text accompany severity colors).
- **i18n-ready:** user-facing strings centralized in `src/lib/i18n/strings.ts` (keyed), added to
  framework later; timezone/currency per org.
- **Observability:** structured JSON logs (request id, org id only — no PII in logs), `/healthz`,
  job dead-letter alerts go to the in-app notification channel.
- **Soft deletes:** `deleted_at` on machines, inventory items, suppliers, documents, templates,
  sites, areas. Hard delete rules per brief 5.6 (history-bearing machines can never be hard deleted).

## 10. Testing strategy

| Level | Scope |
|---|---|
| Unit | metric math (MTBF/MTTR/uptime/compliance/planned-ratio/backlog), WO state machine transitions, inventory ledger invariants (never silently negative; running balance exact; reservations), signature verification, CSV parsers, cost roll-ups, kobo money math |
| Repo/integration | Drizzle queries against PG (testcontainers), scheduling/generation logic, report builder |

| E2E (Playwright) | login → guided machine add → CSV import → create WO → run checklist → issue parts (stock decrements) → complete → verify → report PDF; repair-request compile → edit brief → confirm → mock marketplace completion → root cause feedback |

## 13. Risks & assumptions

- VIDE backend is only reachable on a dev device today (`127.0.0.1`); production URL/webhooks unknown → mock-first, contract tests define the interface (never invent silent assumptions).
- Design tokens extracted from one page; other VIDE pages may extend the palette — rare cases flagged rather than guessed.
- Monospace-dense design at tiny sizes: mitigated with the 12px floor agreed in §3.3 (confirm in Q4).
- Marketplace service doesn't exist yet: the contract we define becomes the *input* the marketplace team builds against (or adapts).
- Next.js server actions vs route handlers mix kept minimal and consistent: reads via handlers (cache-friendly), writes via services only.
